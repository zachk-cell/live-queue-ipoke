iPoke Live Queue — Operator Guide

Everything you need to run the iPoke order board: reading the queue, working the fulfill loop, running Events (Quacks & WTAs), and keeping the Vault, overlay, and Discord in sync. Skim it once, keep it open on the side.

Platform: Shopify Runs: Perpetual · 24/7 Timezone: Pacific (PST/PDT) Tracker: Vault Events: Quacks & WTAs

What iPoke is (30-second version)

iPoke is a running-order board for a Shopify trading-card seller. Both TikTok Shop orders and native web orders funnel into one Shopify store, and iPoke polls the Shopify Admin API for new paid orders — it does not talk to TikTok directly. Because iPoke is perpetual, ingest runs 24/7: there is no "go live" gate to start orders flowing. You pack from the top down — read the flags, print the label, drop the cards in, hit ✓ Fulfilled. Event line items (Quacks & WTAs) peel off into their own side-queues; Vault bundles tally into the Vault counter. That's the whole job.

🧪 Want to practice? Open the interactive sandbox ↗ — a safe copy of the board loaded with fake orders. Add orders, print labels, fulfill, bump, undo… you can't break anything, and it never touches the real queue. Perfect for training a helper.

1 Get into the admin

  • Open the admin link you were given (a secret URL — don't share it or show it on stream). The board also has a public page at the root URL that shows buyers only their position and username — no prices, no controls.
  • Log in with the password. The guide and sandbox sit behind the same server-side gate.
  • Start of every session: hard-refresh (Ctrl/Cmd+Shift+R) so you're on the newest build.
Two views, never mix them: the public page is safe to show on stream; the admin panel (secret URL) is where you work — never screen-share it.

2 How orders arrive (perpetual, from Shopify)

iPoke polls the Shopify Admin API roughly every 10 seconds for new paid, non-cancelled orders and drops each into the queue. On boot it looks back a few hours so a restart never loses orders, and ingest is idempotent (the same order is never added twice).

  • No "Go Live" needed for ingest. iPoke is perpetual — orders flow in around the clock. You don't have to arm anything to start receiving them.
  • An order shows up only once Shopify marks it paid. If a buyer checked out but hasn't paid, it hasn't landed yet — that lag is upstream, not the board.
  • Both channels land in the same Shopify store, so TikTok-channel and web orders sit in one queue. iPoke folds the Shopify variant into the item name so priority, event, and Vault matching all see it.
The TikTok ON_HOLD trap: Shopify marks every TikTok-channel order ON_HOLD by default (the TikTok channel manages fulfillment). That is not a real hold — it's noise, and iPoke ignores it. iPoke only raises the ⚠ ON HOLD flag for a genuine web-order hold, where a person deliberately held the order. So a hold flag on iPoke means something; don't panic over TikTok orders.

3 Read the board

Each row is one buyer's bag. Repeat orders from the same buyer merge into one slot. The top bar shows running totals (in queue, priority, queue value, fulfilled). Ordering, top to bottom:

  1. A manually bumped slot (always #1 until fulfilled).
  2. Priority-item buyers, earliest priority purchase first.
  3. Normal buyers, earliest order first.

Event line items (Quacks & WTAs) are routed out of the main queue into their event's side-queue, so they don't clutter the main line.

4 Flags & badges — what each one means

PRIORITY Order contains a configured priority item (matched inside the item name). Priority buyers sort above normal ones. Manage the list from ⭐ Priority items. N orders This buyer has more than one active order merged into this one slot — pack them together. ＋ ADDED MORE The buyer ordered again while already at the top (#1). Add it to the bag in progress before you fulfill. The expanded view lists what was "Added since top of queue." ⚠ SAME NAME A different buyer shares this exact display name. Keyed on buyer id, so a single buyer's own repeat orders are never falsely flagged. An id …xxxx tag appears to tell them apart. 🔁 N earlier today This buyer already had order(s) fulfilled earlier this stream — decide whether it should have been combined. ⚠ ON HOLD A genuine web-order fulfillment hold on Shopify. (Remember: TikTok's default ON_HOLD is not flagged — iPoke filters that noise out.) 📦 PREPPED You marked this slot prepped / ready to fulfill — a visual "bag is packed, ready to hit fulfill" marker. It does not reorder the queue; it just turns the slot green. OVERSOLD Seen inside an event — an order landed beyond the event's spot cap. It's captured and flagged, never dropped (see §7).

5 The fulfill loop

  1. Work the top row. Read its flags first — combine merged orders, add any "＋ ADDED MORE" items, and check for an ⚠ ON HOLD before you ship.
  2. Hit 🏷 Label to print the 2.25×1.25 bag label (username, order numbers, and a same-name id tag when needed).
  3. Pack the cards. Optionally tap 📦 to mark the slot prepped if a helper packs and you fulfill separately.
  4. Hit ✓ Fulfilled. The slot drops into Fulfilled today and the counters update.

Other row actions

  • ▲ Bump — force a slot to #1 (e.g. a VIP or a fix). It stays on top until fulfilled.
  • ✕ Remove — buyer cancelled: the order leaves the queue and is not counted as fulfilled. (Undo/Restore from the Fulfilled/Cancelled sections.)
  • Hold / set-aside — pull a slot out of the working line without cancelling it. (This manual set-aside is separate from the Shopify on-hold flag.)
  • Combine — merge repeat orders (by time window or same name) into a single slot when a buyer's orders should ship together.

6 The expanded order view

Click the caret ▸ on any row to expand it. You'll see every line item, grouped by order number when the slot holds more than one order, plus a clearly separated "＋ Added since top of queue" group and the full order number(s) at the bottom. Use it whenever a slot has several orders or an "ADDED MORE" flag so nothing gets missed in the bag.

7 Events — Quacks & WTAs

An event is a side-queue for a specific drop: a Quack Pack or a WTA (winner-take-all). Any order whose line item matches an event's keyword is pulled out of the main queue and into that event's roster, so events don't clog the main line. Keyword matching is apostrophe-safe — it matches whether the Shopify title uses a straight ' or a curly ’ apostrophe.

Spot caps & oversold capture

  • Each event has a Total spots cap. The roster is served first-in-first-out (purchase order, no skipping).
  • When orders exceed the cap the event shows OVERSOLD 27/25 · +2 over. Oversold seats are captured and flagged, never dropped — you decide how to handle them.
  • Straddling the cap: if one multi-spot order has some spots within the cap and some beyond it, the whole entry is flagged OVERSOLD ×2 and marked a partial/straddler, and the roster tells you exactly how many of that order's spots are over the line. So a buyer who bought the last seat plus one extra is never silently split or lost.
  • Leave the cap at 0 / blank to run an event untracked — it still captures matching orders, just without a cap.

Sync events from the Shopify catalog

Events don't have to be typed by hand. Each event is a variant of one Shopify product (the "Quack Pack Series" product). Hit Sync from Shopify to pull a review list of every variant that isn't already an event:

  • Seat counts are prefilled from Shopify on-hand inventory (on_hand). Blank = untracked (tracks orders immediately, no cap).
  • Tick the ones you want and add them in one go — no re-typing keywords or seat counts.
  • A periodic auto-sync (about every 5 minutes) quietly pulls in newly-listed events, so a drop added to the catalog mid-stream shows up on its own. Requires the read_products, read_inventory, and read_locations Shopify scopes.

Working an event & Past Events

  • Fulfill spots one at a time from the roster as you work through the drop (each spot toggles done). A fulfilled spot still counts toward the cap — capacity is not freed, so you can't accidentally oversell by fulfilling.
  • Rip marks every spot fulfilled and closes the event (stops taking new orders) once it's been ripped on stream.
  • Archive to Past Events saves the event and its full roster, then clears it off the board. Review any past drop later on the Past Events page.

8 The Vault counter

The Vault is iPoke's per-variant tracker — a cumulative tally of tracked bundle variants that persists across streams. Add a Vault by giving it a display name and an item name / keyword to match. Each Vault card shows a live count you can edit, Save, or Reset, with a recoverable edit/reset log.

  • Counts at the top: a Vault order adds to the counter when it reaches the top of the queue (+1 per unit; tiered "(N Vault)" variants add N).
  • Off-top grace: an order fulfilled without ever reaching the top still counts — but only after a short grace window (~10 min) of staying fulfilled, so a quick undo doesn't miscount. Either way, a given order is counted exactly once, ever.
  • The Vault shows on the public page, has its own overlay, and is mirrored into Discord.

9 Stream overlay & Vault overlay

Add the overlay in OBS as a Browser Source pointing at /overlay (transparent background). There's a separate Vault overlay at /overlay/vault.

  • Reel mode (/overlay?reel=1) slowly auto-scrolls the whole queue — and the roster of the active event — looping seamlessly, so viewers can watch the line move.
  • Adjust scale, background transparency, show/hide the panel, and reel scroll speed live from the overlay controls in the admin panel. Whichever event you toggle active is the one shown on the overlay.

10 Find an order fast

  • Search box — filter by buyer name or order # (full number or just the last few digits).
  • Page size — the "Show N" dropdown sets how many rows per page (default 25) for big lines.

11 Discord mirror

When enabled, a bot keeps auto-updating messages in your channel:

  • The live queue message (buyers in line).
  • The Vault tracker message.
  • An Events — Quack Packs & WTAs message with each open event's spot count; full rosters live in a thread on it. The event currently on the overlay is marked 🔴 LIVE — on stream now.
